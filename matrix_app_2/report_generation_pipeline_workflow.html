Architecture Reference

How matrix_app turns freeform briefs into audited PDF reports

Complete technical specification of the report generation architecture: five entry paths converging on verified MySQL data, a high-fidelity Section-by-Section Batching Engine that eliminates LLM data loss, a Protected Editorial Evidence Design System with visible printout URLs, and headless Chromium PDF compilation.

Traced directly from services/dynamic_report_service.py, services/adhoc_generation_service.py, adhoc_report_sidecar/, ollamaagent2.py, and server.py.

01The mental model

Every report generation path in MATRIX is governed by a strict separation of concerns between visual layout authoring and verified data compilation.

03Preview → Edit Loop → Confirm, step by step

Tracing the execution life-cycle of the Ad-Hoc Freeform AI Report pipeline from user prompt to final verified PDF.

  1. 1. Trigger & Intent Routing

    ollamaagent2.py · _is_freeform_report_request()

    Chat messages containing both a report intent ("report", "dossier", "briefing", "pdf") and styling/layout directives ("newspaper style", "dark theme", "executive dashboard", "boxed cards", "2-column") are routed to the ad-hoc pipeline. Standard queries without styling trigger the component checklist.

  2. 2. Deterministic Scope Resolution

    services/dynamic_report_service.py · resolve_report_scope()

    Resolves target entity: explicit topic ID, quoted topic title, conversational pronoun ("this topic"), or temporal range ("trending past 7 days"). Refuses ambiguity without hallucinating.

  3. 3. Brief Extraction

    services/dynamic_report_service.py · _extract_report_brief()

    LLM extracts structured JSON: {content_focus: [...], design_notes: "..."}, mapping desired sections, palette, audience, and constraints.

  4. 4. Sidecar WebSocket Code Generation

    services/adhoc_generation_service.py · generate_layout_html()

    Connects to adhoc_report_sidecar at ws://127.0.0.1:7001/generate-code. Streams system prompts instructing the model to generate a clean, self-contained HTML/CSS layout with realistic placeholder metrics and Chart.js canvases. Returns full HTML upon receiving variantComplete.

  5. 5. Draft Slot Layout & Pending Persistence

    reports/templates/_pending/<template_id>/

    Saves template.html, layout.json, and meta.json under _pending/ directory. No database mutation or PDF render is performed at this stage.

  6. 6. Checkpoint: Interactive Live Preview Card

    frontend/js/script.js · buildAdhocReportPreviewCard()  |  frontend/js/report-builder.js

    Renders the placeholder HTML in a sandboxed <iframe> inside the chat or Report Builder UI. Displays the template name, preview iframe, a "🔄 Update / Regenerate Preview" refinement box, and a "✓ Looks good, Build Report (PDF)" confirmation button.

  7. 7. Post-Preview Refinement / Edit Loop (Optional)

    ollamaagent2.py · report_builder_node  |  POST /api/reports/preview-freeform-adhoc

    If the user enters refinement feedback (e.g. "Make it 2 columns and use newspaper styling") and clicks regenerate, the pipeline re-extracts the brief, merges new design notes, re-calls the sidecar WebSocket, updates the pending files, and re-renders the live preview.

  8. 8. Confirmation & Template Promotion

    services/dynamic_report_service.py · confirm_adhoc_report()

    Clicking confirm copies the draft from reports/templates/_pending/<template_id>/ into the permanent library at reports/templates/<template_id>/ and launches ground-truth data binding.

  9. 9. MySQL & Live API Data Gathering

    services/dynamic_report_service.py · fetch_topic_report_data()

    Fetches verified MySQL metrics: total posts, sentiment distribution, platform breakdown, hourly/timeline trends, top post bank with URLs and authors, plus live API enrichment (district escalations). Rejects empty topics.

  10. 10. Section-by-Section Batching Engine

    services/dynamic_report_service.py · render_from_template_by_sections()

    BeautifulSoup decomposes the HTML into independent sections (cards, tables, evidence grids). Each section receives its targeted sub-dataset without truncation. A dedicated script reskin pass updates Chart.js datasets. The DOM is reassembled seamlessly with global CSS preserved.

  11. 11. Anti-Fabrication Content Audit & Redaction

    services/dynamic_report_service.py · _redact_high_confidence_fabrications() & _call_content_audit_llm()

    Scans text nodes for numeric and named entity tokens. Raw post quotes, source handles, and URLs are exempted from redaction. Any ungrounded hallucinated numbers are replaced with Not available.

  12. 12. Headless Chromium PDF Compilation

    services/dynamic_report_service.py · sync_playwright()

    Playwright launches headless Chromium, injects print-friendly CSS rules (break-inside: avoid !important), captures canvas rendering, and exports reports/<report_id>/report.pdf.

⚠
Sidecar Failover Architecture: If the sidecar WebSocket at port 7001 is unreachable or times out, the chat agent gracefully catches the exception and immediately falls back to Method 3 (Curated Template Match), generating an audited PDF without blocking the user.

05The Section-by-Section Batching Engine

How MATRIX guarantees zero data loss and prevents context blowout during large template reskinning.

The Problem: Single-Pass Context Blowout

When feeding an entire 150KB HTML document containing multiple charts, KPI grids, tables, and 20 top posts into a single LLM prompt, context limits force aggressive trimming (capping keywords to 15 → 3 → 1, dropping post texts). The model often truncates output or hallucinates values.

The Solution: Section-by-Section Batching

render_from_template_by_sections() uses BeautifulSoup to break the template into independent visual sections. Each section receives only the relevant sub-dataset (100% untruncated), gets reskinned by a fast LLM pass, and is seamlessly reassembled into the document DOM.

Architectural Decomposition Steps

  1. DOM Section Extraction: Identifies top-level <section>, <article>, .card, or major container blocks while preserving global <head>, <style>, headers, and footers.
  2. Targeted Sub-Dataset Filtering:
    • Sentiment / Analytics section: Receives full sentiment counts, percentages, and emotion breakdowns.
    • Platform / Channel section: Receives complete platform distributions and engagement totals.
    • Evidence / Key Posts section: Receives all top posts with author handles, full text, timestamp, and full URLs without truncating text length.
  3. Per-Section LLM Reskin: _call_section_reskin_llm() reskins the isolated HTML snippet, strictly outputting valid HTML for that section alone.
  4. Chart.js Script Reskinning: _call_script_reskin_llm() analyzes <script> tags and updates Chart.js dataset arrays (labels, data points, background colors) to match real MySQL numbers.
  5. DOM Reassembly: Replaces original section nodes with updated reskinned nodes and outputs a fully unified, valid HTML document for auditing.

06Protected Evidence & Editorial Newspaper CSS

Standardizing visual containment, layout flow, and printout-friendly evidence rendering for police and executive briefings.

Card Containment & Boxing

Every analytical section, KPI block, and post card is enclosed in strict structural containers (border, border-radius, box-shadow, padding), preventing text from bleeding across columns.

Page-Break Safety

Injects break-inside: avoid !important; page-break-inside: avoid !important; into every card and post container to prevent split cards or fragmented headings across PDF pages.

Visible Printout URLs

Evidence cards print clickable https://... raw links directly in an .evidence-urls-container so physical paper prints provide complete reference links for officers.

Editorial Newspaper Design Principles

The newspaper/intelligence aesthetic utilizes clean typography hierarchies (editorial serif headers with clean sans-serif body text), sentiment-coded accent borders (crimson for negative/escalation, emerald for positive, amber for neutral), and structured metadata pills (platform badges, engagement counters, verified timestamps).

07Fabrication Audit & Redaction Rules

Strict verification mechanics ensuring zero hallucinated metrics or unauthorized claims reach the PDF.

Exempted Real Post Evidence

Raw text, quotations, user handles, and URLs extracted from verified MySQL post_bank records are strictly protected from redaction. The audit engine recognises verbatim quotes and excludes them from false-positive flagging.

Dynamic Date & Stoplist Normalization

Dates are dynamically expanded (e.g. 2026-09-08 matches "Sep 8, 2026" or "08-09-2026"). The expanded _NAMED_PHRASE_STOPLIST prevents standard analytical terminology from being redacted as "Not available".

The 4-Step Anti-Fabrication Pipeline

  1. Token Extraction: Scans rendered HTML text nodes for numbers, percentages, and named phrases, ignoring CSS/JS attributes and URLs.
  2. High-Confidence Pre-Filter: Instantly redacts ungrounded 6+ digit numbers not present in MySQL data.
  3. LLM Audit Verdict: Compares remaining candidates against full REAL_DATA_JSON, classifying each as verified, structural, or unverified.
  4. Fail-Closed Redaction: Replaces unverified tokens with <span class="unverified">Not available</span> in text nodes without breaking HTML syntax.

08How to use each method

Guidelines for selecting the optimal pipeline based on user requirements and access level.

Chat Component Reports (Method 1)

Ask for a topic summary without design keywords (e.g. "Generate a report for Gorakhpur protest"). Select desired components in the interactive checklist card.

Admin Component Builder (Method 2)

Navigate to /report-builder (Tab 1), select the verified topic, toggle desired component sections, and click Generate.

Curated Template API (Method 3)

Call POST /api/reports/generate-freeform with design parameters for programmatic generation without preview checkpoints.

Uploaded Custom Template (Method 4)

Upload a custom UTF-8 .html file in /report-builder (Tab 2). Select a topic to compile via Section Batching.

Ad-Hoc AI Design with Edit Loop (Method 5)

Provide a detailed visual prompt in chat or /report-builder (Tab 3). Review the live HTML preview, refine via the edit box if desired, and click confirm to generate the PDF.

10FAQ for newcomers

How does Section-by-Section Batching prevent data loss?
Instead of dumping 20 posts and dozens of metrics into a single huge prompt that exceeds LLM output limits, BeautifulSoup splits the HTML into individual card/section snippets. Each section is reskinned independently with its full sub-dataset, guaranteeing that 100% of posts and metrics are rendered without truncation.
How does the Post-Preview Edit Loop work?
When viewing the live preview inside the chat or Report Builder UI, the user can type revision notes (e.g. "Change background to dark theme and make it 2-column") in the edit box and click Update / Regenerate Preview. The backend re-extracts the brief, regenerates the draft HTML via the sidecar, and updates the preview iframe before any real MySQL data is fetched.
Why are full URLs printed directly in the Evidence Section?
Intelligence and police reports are frequently printed out on physical paper. Standard inline hyperlinks (<a href="...">View Post</a>) become useless once printed. The editorial design system renders full clickable https://... URLs directly inside the evidence card so officers can reference them from paper.
What happens if the sidecar service on port 7001 is offline?
The chat agent catches the connection failure and automatically falls back to Method 3 (Curated Template Match), selecting the best matching hand-crafted template from the library and compiling the PDF immediately without breaking the user turn.
