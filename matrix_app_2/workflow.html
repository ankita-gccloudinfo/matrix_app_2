1. Query Ingestion 3 Nodes
query_rewriter ENTRY

Normalizes user prompt; grounds ambiguities via 7 web questions if needed.

query_manager

Reconstructs follow-up turns into a single self-contained standalone query.

check_query_manager ROUTER

Evaluates query accuracy; routes to keyword grounding if topic detected.

Exit ➔ Keyword / SQL
2. Entity Grounding 4 Nodes
keyword_of_post_maker

Generates EN/Hindi spellings, hashtags & entities via `recycle_search` table.

go_duck_search WEB DUCK

Live web search fallback for unknown slang or short-forms.

keyword_checker

Filters hallucinations & builds clean SQL LIKE combinations.

go_duck_search_verify VERIFY

Secondary verification check if all keywords were dropped.

Exit ➔ table_selector
3. MySQL Engine 5 Nodes
table_selector

Selects exact minimal tables (topic, analyzed_data, post_bank, etc.).

generate_sql

Writes optimized MySQL with date partition pruning and Hindi/EN LIKE.

sql_judge LOOP

Audits query logic vs intent. Triggers retry on logic failure.

is_safe_sql GUARD

Deterministic AST safety check. Blocks mutations/DDL/injections.

execute_sql

Runs against MySQL. 0 rows triggers Vector/Graph Fallback.

0 rows ➔ Fallback | Data ➔ Synth
4. Fallback Network 4 Nodes
fallback_decider

Decides between Qdrant vector index search or Neo4j graph query.

content_index_search QDRANT

Embeds query and searches dense vector index for topic IDs.

neo4j_search NEO4J

Traverses knowledge graph relationships, authors & district tags.

fallbackchecker

Injects discovered topic IDs back into MySQL table_selector retry.

Hint ➔ table_selector Retry
5. Synthesis & Audit 4 Nodes
llm_validator

Batch-processes rows, extracts sentiment percentages and metrics.

judge_and_reason

Synthesizes evidence, structures timeline and district breakdown.

answer

Generates conversational markdown response with source links.

answer_checker FINAL

Hallucination check & completeness audit before sending to user.

Exit ➔ END (User Response)
